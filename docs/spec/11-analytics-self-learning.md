## GLOBAL OBJECTIVE

Измеряет эффективность, находит закономерности, помогает улучшать контент и процессы **без
нарушения стиля** каждого канала. **Предоставляет данные и рекомендации — не решает за AI Engine.**

---

## Переформулировка: надёжная аналитика здесь — внутренняя

Ключевая правда, определяющая ценность модуля: **самые надёжные метрики не зависят от Telegram
engagement**, который на Bot API недоступен (Часть 7/10). Разделяем:

| Группа | Надёжность | Зависит от Telegram engagement? |
|---|---|---|
| **Cost** (токены, стоимость, прогноз бюджета) | ✅ высокая | нет |
| **Quality** (quality/similarity score, регенерации, отклонения) | ✅ высокая | нет |
| **System** (время генерации/публикации, ошибки, ретраи, throughput) | ✅ высокая | нет |
| **Content diversity** (баланс тем/типов/CTA/изображений) | ✅ высокая | нет |
| **Engagement** (просмотры, ER, CTR, реакции) | ⚠️ **gated/недоступно** | да |

> Вывод: модуль **ценен и без просмотров** — он оптимизирует стоимость, качество, надёжность и
> разнообразие. Engagement — отдельный, gated пласт.

---

## Разрешение сигнала обучения (финально)

Что реально доступно для награды bandit (Часть 5) **без** per-post метрик:

- рост подписчиков по временным окнам (`getChatMemberCount`, снимки);
- клики по трекинг-ссылкам (если ссылки размечены UTM/редиректом);
- внутренние прокси: quality score, уникальность, доля регенераций.

**Проблема:** это низкое разрешение — «какой из вчерашних постов сработал лучше» так почти не
измерить (рост подписчиков не атрибутируется конкретному посту). Значит награда bandit **шумная
и слабая**.

**Рекомендуемый разблок — read-only MTProto stats-адаптер:**

- Telegram отдаёт broadcast-статистику канала (просмотры/пересылки/рост) через MTProto для
  каналов, где аккаунт **админ** — это **чтение статистики**, не постинг user-аккаунтом;
- сам постинг остаётся на Bot API (Часть 7); адаптер — отдельный, только на чтение, за
  интерфейсом провайдера;
- это единственный путь к per-post views/ER → полноценному сигналу обучения.

> Решение (включать адаптер или жить на слабом сигнале) — за владельцем; спека фиксирует, что
> **без него self-learning опирается на прокси-метрики и рост подписчиков**, а не на per-post ER.

## DATA COLLECTION

После публикации сохраняются доступные метрики: дата · канал · тип · тема · персона · модель ·
генератор изображений · размер текста · наличие изображений · статус. Доп. показатели (просмотры/
реакции) — **если** доступны (адаптер выше). Пишется задачей `collect_metrics` (Часть 8).

## METRIC GROUPS

**Content:** число публикаций, средняя длина, число изображений, темы, CTA.
**System:** время генерации/публикации/проверки, ошибки, ретраи.
**Cost:** стоимость текста/изображений/эмбеддингов, общая, по каналам.
**Quality:** средний quality score, средняя уникальность, число регенераций, отклонения.

Первые четыре — надёжны (внутренние). Engagement — отдельно, gated.

## Governance: что self-learning МОЖЕТ и что ЗАПРЕЩЕНО (граница с Частью 5)

Черновик верно требует контролируемости. Чёткая граница:

**Может автоматически (в пределах bandit, Часть 5):**

- корректировать **вероятности выбора** тем/CTA/структуры/времени (руки bandit);
- с обязательным **полом исследования** (`epsilon_min`) — разнообразие не схлопывается;
- медленно и регуляризованно (защита от шума).

**ЗАПРЕЩЕНО менять автоматически (только через администратора):**

- базовый стиль канала;
- биографию/характер персоны;
- ключевые правила генерации;
- системные промпты.

> Это и есть разделение: bandit крутит **выбор** внутри безопасного множества; всё, что меняет
> **идентичность** канала, — человеческое решение. Рекомендации таких изменений модуль формирует,
> но **не применяет**.

---

## ⚠️ A/B: классический сплит аудитории в Telegram НЕВОЗМОЖЕН

Черновик хеджирует «разделять аудиторию (если платформа поддерживает)». **Не поддерживает:**
канал вещает **всем** подписчикам один и тот же пост — разделить аудиторию внутри канала нельзя.

Значит доступны только более слабые схемы (с confounding, честно):

- **Temporal (последовательный):** чередовать варианты во времени, сравнивать — искажается
  сезонностью/временем;
- **Cross-channel:** один вариант на группе похожих каналов — искажается различиями каналов.

Оба требуют достаточной выборки и осторожной статистики; результаты — гипотезы, не доказательства.

## EXPERIMENT MANAGER (твоё дополнение — на реальном ограничении)

- запускает **temporal/cross-channel** эксперименты (не audience-split — см. выше);
- результаты хранятся **отдельно**, не смешиваются с основной статистикой;
- безопасное вкл/выкл без влияния на основную систему;
- пре-продакшн проверки — в AI Studio (Часть 10, dry-run).

## Аналитические разделы

- **Report generation:** ежедневные/еженедельные/месячные/пользовательские — задачи планировщика (Часть 8).
- **Channel report:** динамика публикаций, темы, типы, CTA, качество, ошибки, затраты.
- **Content analysis:** частые/редкие/давно не появлявшиеся темы, баланс типов, разнообразие →
  при перекосе **сообщает и предлагает** правку контент-плана (не применяет сам).
- **Image analysis:** повтор локаций/ракурсов/цветов/образов → при однообразии повышает
  разнообразие в следующих генерациях (окна Части 1/6).
- **CTA analysis:** частота/история/контекст → рекомендация разнообразить.
- **Style consistency:** контроль соответствия профилю (структура, лексика, эмоц. профиль, длина,
  оформление) — это **обратная связь для Style Memory** (Часть 9); при устойчивом дрейфе —
  сигнал администратору. Требует style-экстрактора (оговорка Части 9).
- **Schedule analysis:** распределение по времени, равномерность, пропуски, нагрузка по дням →
  рекомендации по расписанию.
- **Error analytics:** повторяющиеся ошибки, нестабильные сервисы, частота отказов, MTTR.
- **Cost analysis:** по дням/неделям/месяцам/каналам/моделям/сервисам + **прогноз бюджета**
  (надёжный, высокоценный выход).
- **Trend detection:** рост публикаций, сдвиг тем, нагрузка, стоимость, качество.
- **Quality dashboard:** средний quality/similarity score, регенерации, успешные публикации,
  распределение оценок.

## RECOMMENDATION ENGINE

Формирует рекомендации (разнообразить темы/CTA, обновить KB, пересмотреть настройки качества,
оптимизировать расходы). **Не применяются автоматически**, если меняют стратегию канала без
подтверждения.

## OBSERVABILITY

Каждый расчёт: дата · источник данных · фильтры · **версия алгоритма** · время выполнения →
воспроизводимость.

## FUTURE EXTENSIBILITY / DESIGN PRINCIPLES

Новые отчёты/метрики/алгоритмы/внешние источники — без переработки. **Analytics не принимает
окончательных решений за AI Engine** — даёт достоверные данные и рекомендации.

## Reconciliation

- Надёжная аналитика — **внутренняя** (cost/quality/system/diversity); engagement — gated.
- Сигнал обучения без адаптера — прокси + рост подписчиков (слабый); полноценный — только через
  **read-only MTProto stats-адаптер**.
- Граница self-learning: bandit крутит **выбор** (с полом исследования); идентичность канала
  (стиль/персона/промпты) — только человек.
- **A/B со сплитом аудитории невозможен** в Telegram → temporal/cross-channel (с confounding).
- Style consistency = обратная связь для Style Memory (Часть 9).
- Расчёты/отчёты — задачи планировщика (Часть 8) с версией алгоритма.
